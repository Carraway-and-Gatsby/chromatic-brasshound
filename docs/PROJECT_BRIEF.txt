==================================================
2. CREATIVE VISION
==================================================

BRASSHOUND takes place in a fictional industrial
world devastated by malfunctioning autonomous
military machines.

A powerful corporation called BLACKFORGE INDUSTRIES
has lost control of its automated weapons network.

Entire industrial cities are now occupied by
mechanical infantry, drones, turrets, and
massive armored war machines.

The player controls ROOK, the last surviving
member of an elite special operations unit
known as BRASSHOUND.

ROOK must infiltrate enemy-controlled territory,
destroy hostile machines, and disable their
central command systems.

The first mission, OPERATION CINDER, takes place
in a ruined industrial city.

The mission culminates in a battle against
IRONMAW, a gigantic armored combat vehicle.

Creative Direction:

- Energetic
- Expressive
- Mechanical
- Explosive
- Slightly humorous
- Highly replayable
- Easy to understand
- Difficult to master

The game should feel like a lost handheld
action game from the late 1990s.

Avoid excessive dialogue and cinematic interruptions.

GAMEPLAY COMES FIRST.

==================================================
3. CORE GAMEPLAY
==================================================

Implement a responsive side-scrolling action system.

PLAYER MOVEMENT

The player must be able to:

- Move left and right
- Jump
- Shoot while standing
- Shoot while jumping
- Shoot while moving
- Crouch
- Shoot while crouching
- Face left or right
- Aim upward if technically feasible

Movement must feel immediate and predictable.

Prioritize low input latency and responsive controls.

PLAYER CONTROLS

D-Pad Left/Right:
Movement

D-Pad Up:
Aim upward

D-Pad Down:
Crouch

A:
Jump

B:
Fire weapon

Hold B:
Automatic repeated firing according to weapon fire rate

START:
Pause / Resume

SELECT:
Switch weapons when multiple weapons are available

Make sure simultaneous movement, jumping, and
shooting work correctly.

==================================================
4. COMBAT SYSTEM
==================================================

Build a functional combat system with:

- Player projectiles
- Enemy projectiles
- Projectile collision detection
- Damage handling
- Enemy health
- Player health
- Destructible objects
- Hit animations
- Death animations
- Explosion effects
- Invulnerability frames after player damage

WEAPONS

Weapon 1: Standard Pistol

- Unlimited ammunition
- Moderate fire rate
- Single projectile
- Reliable default weapon

Weapon 2: Heavy Machine Gun

- Faster firing rate
- Limited ammunition
- Obtainable through an item pickup
- Distinctive visual and audio feedback

Weapon 3: Rocket Launcher

- High damage
- Slow firing rate
- Explosion effect
- Unlock after the initial gameplay systems are stable

Each weapon must feel different.

Prioritize satisfying impact feedback:

- Muzzle flashes
- Impact particles
- Enemy hit reaction
- Brief explosion animations
- Distinct audio feedback

Avoid expensive effects that compromise
hardware performance.

==================================================
5. ENEMY SYSTEM
==================================================

Implement at least three distinct enemy types.

ENEMY TYPE A: MECHANICAL INFANTRY

Behavior:
- Patrols a small area
- Detects nearby player
- Fires horizontally
- Can be defeated with several hits

ENEMY TYPE B: DEFENSE TURRET

Behavior:
- Stationary
- Fires periodically
- Has predictable firing intervals
- Can be destroyed

ENEMY TYPE C: FLYING DRONE

Behavior:
- Moves along a simple flight path
- Attacks or approaches the player
- Has relatively low health
- Creates movement pressure

ENEMY AI REQUIREMENTS

Use lightweight deterministic state machines.

Example states:

IDLE
PATROL
ALERT
ATTACK
HIT
DESTROYED

Enemy attacks should be readable and avoid
unfair unavoidable damage.

Do not overload the screen with enemies.

Use hardware-aware limits on active enemies
and projectiles.

SECTION B:
Industrial Streets

==================================================
7. BOSS BATTLE: IRONMAW
==================================================

Create a memorable mechanical boss.

IRONMAW is an enormous armored vehicle.

Visual Characteristics:

- Large armored body
- Heavy industrial construction
- Prominent main cannon
- Mechanical moving components
- Glowing vulnerable core
- Expressive damage animations

The boss should appear significantly larger
than ordinary enemies.

Use background tiles and carefully managed
sprites when appropriate.

BOSS BEHAVIOR

Implement at least two attack phases.

PHASE 1:
- Fires slow projectiles
- Uses predictable firing intervals
- Allows the player to understand attack patterns

PHASE 2:
Triggered when health falls below a threshold.

- Faster attack intervals
- Additional projectile patterns
- More aggressive behavior
- Visual indication that the boss is damaged

WEAK POINT

The boss must have a recognizable weak point.

The player should be rewarded for correctly
timing attacks against it.

BOSS DEATH

When defeated:

- Stop boss attacks
- Play an explosion sequence
- Display visible destruction
- Transition to MISSION COMPLETE

Keep effects compatible with Game Boy Color
hardware limitations.

The boss should feel exciting, not unfair.

==================================================
11. HARDWARE CONSTRAINTS
==================================================

This project must run on actual Game Boy Color
compatible hardware.

The target device is ModRetro Chromatic.

Respect the following constraints:

- 160x144 display
- Limited video memory
- Limited sprite count
- Maximum 10 hardware sprites per scanline
- Maximum 40 hardware sprites total
- Limited color palettes
- Restricted CPU and memory resources
- Limited simultaneous audio channels

Use tile-based backgrounds and efficient
sprite reuse.

Use sprite-based entities only where necessary.

Design large mechanical bosses with hardware
limitations in mind.

Optimize projectile counts and enemy counts
based on actual performance.

Prioritize stable gameplay over visual complexity.

Do not use floating-point physics if fixed-point
or integer arithmetic is sufficient.

Do not add runtime dependencies on internet
services or external APIs.

The ROM must function entirely offline.
